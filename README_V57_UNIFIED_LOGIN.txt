FLEVO WEBSITE — VERSION 5.7
UNIFIED SUPABASE LOGIN

هذه النسخة امتداد مباشر للنسخة:
FLEVO_Website_Supabase_v5_6_NEON_PROFILE_CONTACT

لم يتم إنشاء موقع منفصل أو تغيير هيكل المشروع السابق.

التعديلات المنفذة

1. توحيد كارت تسجيل الدخول داخل صفحات الإدارة:
   - dashboard.html
   - admin.html
   - quotes.html
   - settings.html
   - services-admin.html

2. إضافة ملفين مشتركين داخل مجلد assets الحالي:
   - assets/unified-auth.css
   - assets/unified-auth.js

3. إزالة نماذج وأكواد تسجيل الدخول المكررة من الصفحات الخمس.

4. استمرار استخدام نفس:
   - إعدادات Supabase الحالية.
   - Publishable Key الحالي.
   - FlevoStore الحالي.
   - قاعدة البيانات والجداول.
   - Storage.
   - RLS Policies.
   - صفحات ومحتوى وتصميم النسخة 5.6.

5. الجلسة الموحدة:
   - تسجيل الدخول مرة واحدة.
   - الانتقال بين جميع صفحات الإدارة دون إعادة تسجيل الدخول.
   - استمرار الجلسة بعد تحديث الصفحة.
   - استخدام Session وAuto Refresh المقدّمين من Supabase.
   - تسجيل خروج موحد من جميع الأقسام.

6. التحويل بعد تسجيل الدخول:
   - روابط الإدارة في index.html وprojects.html وproject.html وgallery.html أصبحت مرتبطة بالمكوّن الموحد.
   - عند الضغط على الإدارة بدون جلسة يظهر كارت الدخول في نفس الصفحة.
   - بعد نجاح الدخول يفتح الرابط المطلوب تلقائيًا.
   - عند فتح صفحة إدارة مباشرة يتم تسجيل الدخول ثم تحميل نفس الصفحة المطلوبة.

7. التصميم:
   - هوية FLEVO Navy / Teal.
   - استخدام شعار FLEVO الأصلي.
   - تصميم موحد للكمبيوتر والموبايل.
   - دعم العربية والإنجليزية بحسب لغة الموقع المخزنة.

اختبار القبول

1. افتح index.html.
2. اضغط رابط الإدارة.
3. تأكد من ظهور كارت FLEVO الموحد.
4. سجّل الدخول.
5. تأكد من الانتقال إلى admin.html.
6. انتقل إلى لوحة القيادة، الطلبات، الخدمات والإعدادات.
7. تأكد من عدم طلب تسجيل الدخول مرة أخرى.
8. نفذ Refresh في أي صفحة إدارة.
9. تأكد من استمرار الجلسة وتحميل الصفحة.
10. اضغط خروج.
11. تأكد من الرجوع إلى index.html.
12. افتح quotes.html مباشرة بدون جلسة.
13. بعد تسجيل الدخول يجب تحميل صفحة طلبات الأسعار نفسها.

ملاحظات النشر

- ارفع هذه النسخة كاملة فوق النسخة الحالية.
- لا ترفع ملف unified-auth.js منفردًا فوق نسخة أقدم.
- لا تستخدم Supabase service_role key داخل الموقع.
- احتفظ بسياسات RLS مفعلة لحماية البيانات.
